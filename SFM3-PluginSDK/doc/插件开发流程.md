# SFM3 插件开发流程（从零到可加载 DLL）

> 版本：1.0.0（2026-09-27）
> 适用场景：在一台**没有 sfm3.0 源码**的电脑上，凭 Plugin SDK 为 SFM Reconstructor 开发新插件。
> 本文档是**操作手册**（怎么做）；契约细节、ABI 红线、参数协议语义见 `doc/插件开发规范.md`（为什么）。
> 二者配合使用：本文每一步都标注了对应规范章节。

---

## 流程总览

```text
[0 环境准备] → [1 获取 SDK] → [2 从模板建工程] → [3 实现三件套]
     → [4 改 .pro] → [5 编译 DLL] → [6 部署上机] → [7 验证加载] → [8 交付]
                     ↑_______________失败时按 §7 故障对照表排查_______________↑
```

---

## 0. 环境准备（一次性）

| 依赖 | 版本 | 说明 |
|---|---|---|
| Qt | **6.10.1** (msvc2022_64) | 必须与宿主完全同版本（红线 #4） |
| 编译器 | **MSVC 2022**（工具集 14.4x），x64 |红线 #5 |
| OpenCV | **4.6.0** world 构建（含 contrib） | 红线 #7，`cv::Mat` 跨 DLL 依赖同版本 |
| ONNX Runtime | **1.26.0** | 仅推理类插件需要 |
| qmake / jom | 随 Qt 安装 | `jom.exe` 在 `Qt/Tools/QtCreator/bin/jom/` |

版本不匹配的下场见规范 §9.1——**这是硬约束，无法绕过**。

## 1. 获取 Plugin SDK

向宿主发布方索取 `SFM3-PluginSDK.zip`（宿主每次升级都会发布配套新 SDK，版本必须匹配），
解压后结构：

```text
SFM3-PluginSDK/
├── include/sfm3/plugin/   # 宿主接口头文件（6 个）——二进制契约，禁止修改
├── lib/sfmcore.lib        # 链接契约——禁止自行重编译接口头（规范红线 #2）
├── pri/common.pri         # 编译配置（OpenCV/ONNX 路径、C++17、NOMINMAX）
├── templates/
│   ├── sample_descriptor/ # 官方描述符模板（确定性伪特征）
│   └── sample_matcher/    # 官方匹配器模板（确定性伪匹配）
├── doc/
│   ├── 插件开发规范.md     # 契约文档
│   └── 插件开发流程.md     # 本文档
└── README.md
```

## 2. 从模板建工程

**不要从空白工程开始**——复制最接近的官方模板改：

| 你的算法类型 | 复制模板 | 实现的接口 |
|---|---|---|
| 描述符（检测/描述特征点） | `templates/sample_descriptor/` | `IDescriptorPlugin` + `IDescriptorWorker` |
| 匹配器（两两描述子匹配） | `templates/sample_matcher/` | `IMatcherPlugin` + `IMatcherWorker` |

建议目录布局（在 SDK **外**建你的工作目录，模板拷入）：

```text
my_aliked_plugin/
├── plugin.json
├── my_plugin.pro
├── MyDescriptorPlugin.h/.cpp   # 工厂（无状态）
├── MyDescriptorWorker.h/.cpp   # Worker（有状态，逐任务独占）
└── <算法本体源码/>              # 如 Aliked.h/.cc + OnnxHelper（自包含，与宿主无关）
```

实现要点（细节见规范第 2/3/4 章）：

1. 工厂实现 4 个元信息函数 + `paramSchema()` + `validateParams()` + `createWorker()`；
2. Worker 构造时从 `QJsonObject` 读参数；`extract(const ImageEntry&)` 返回 `FeatureResult`；
3. **算法本体改造**：算法原实现里的 `exit(-1)` 必须移除（会杀死宿主进程），
   改为抛异常并在 Worker `extract()` 内 catch 后返回空 `FeatureResult`；
   `std::cout/cerr` 打印改 `qWarning()`（走宿主日志系统，可被 UI 收集）；
4. 职责红线：Lowe 比率、几何验证(GRIC)、传递性匹配等编排逻辑**属于宿主管线**，
   插件只做低层算法（规范 §2.3）。

## 3. 起一个全局唯一的 name()

`name()` 返回值即插件 id（如 `"ALIKED"`），全系统唯一且**一经发布不可更改**
（它是用户配置持久化的 key）。与内置算法（SIFT/SURF/KAZE/FLANN/BruteForce）
或其他插件重名时，宿主按"先到先得"注册，你的插件会被跳过。

## 4. 改 .pro（SDK 路径适配，共 3 处）

模板 `.pro` 是宿主工程内写法，SDK 场景改 3 处：

```makefile
# ① common.pri 从 SDK 引入（替换原 include(../../../common.pri)）
SDK_ROOT = $$PWD/../SFM3-PluginSDK        # 按你的目录调整
include($$SDK_ROOT/pri/common.pri)

# ② 接口头路径（替换原 INCLUDEPATH += ../../core）
INCLUDEPATH += $$SDK_ROOT/include/sfm3/plugin

# ③ 链接契约（替换原 LIBS += -L$$OUT_PWD/../../core -lsfmcore）
LIBS += -L$$SDK_ROOT/lib -lsfmcore
```

其余保持模板原样：`DESTDIR` 部署目标、`/IMPLIB` 重定向、ONNX 链接与 DLL 拷贝
（推理类插件照抄 xfeat/superpoint 的 `.pro` 写法，见规范第 5 节）。

## 5. 编译

在 MSVC x64 环境中（Developer Command Prompt / VsDevShell）：

```bat
qmake my_plugin.pro -spec win32-msvc "CONFIG+=release"
jom -j8          :: 或 nmake
```

产物：`<SDK 外的 app 输出>/plugins/my_plugin.dll`。**必须 Release（/MD）**——
debug 插件只能配 debug 宿主（红线 #6）。

## 6. 部署上机

把以下文件放入宿主软件的 `plugins/` 目录（与 `SFMReconstructor.exe` 同级）：

| 文件 | 说明 |
|---|---|
| `my_plugin.dll` | 插件本体 |
| 算法专属运行时 DLL | 如 `onnxruntime.dll`（若宿主 plugins/ 已有则不重复） |
| 模型文件 | 放 `models/` 目录（如 `aliked*.onnx`），Worker 从 `applicationDirPath()/models/` 扫描 |

## 7. 验证加载

启动宿主软件，观察扫描日志（或命令行 stderr）：

```text
[PluginRegistry] 已加载插件: ALIKED ( descriptor )   ← 成功
```

对照故障表：

| 现象（日志） | 原因 | 修法 |
|---|---|---|
| `非 ISfmPlugin` | IID 字符串不一致 / 缺 `Q_INTERFACES` | 对照规范附录 A 逐字符核对（红线 #1/#8） |
| `加载失败: ... Win32 193` | 运行时依赖 DLL 缺失/位数不对 | 补齐 onnxruntime.dll 等（规范第 6 章） |
| 插件加载成功但 UI 不显示 | `name()` 与内置/已有插件重名被跳过 | 换全局唯一 id |
| 加载即崩溃 | 结构体布局/编译器/Qt 版本/CRT 不匹配（红线 #3~#7） | 全部对齐宿主环境重编 |

辅助工具：Qt 自带 `qtplugininfo.exe my_plugin.dll` 可离线确认元数据与 IID 可读（规范 §9.4）。

## 8. 功能验证与交付

1. 用宿主 UI 选择你的算法跑一次完整重建，确认参数表单、特征提取日志正常；
2. 按规范第 7 章的清单核对交付内容（并发一致性等宿主侧测试由发布方执行）；
3. 交付物 = `my_plugin.dll` + 必要运行时依赖 + 模型文件 + 参数说明。

## 附：本机（宿主开发者）开发流程差异

若你**持有 sfm3.0 源码**（仓库内开发），与上述流程的差异仅两点：

- 接口头与 `sfmcore.lib` 直接用仓库内路径（`INCLUDEPATH += ../../core`），
  无需 SDK；`common.pri` 引用仓库根的；
- 验证用 `src/tests/plugin_test`（跑通后随宿主一起交付），
  并按仓库规约在交付前创建 Git commit。

其余步骤（三件套实现、部署、验证方式）完全相同。
